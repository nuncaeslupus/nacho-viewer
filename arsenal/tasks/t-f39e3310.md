### Finding
resolvePath only understands '/'-separated paths (its own comment: 'Linux is the target'), but the app ships msi/nsis/winget builds. For a document at C:\Users\me\notes\a.md, from.split('/') yields one segment, so a link to b.md resolves to '/b.md'; read_document rejects it (not absolute on Windows -> not_permitted) and the tab shows an error. Same for [[wiki]] links and '#frag' on another file.

### Evidence
Traced: backend returns paths via Path::display (backslashes on Windows, dunce-stripped); resolvePath('C:\\Users\\me\\a.md','b.md') -> '/b.md'. links.test.ts has no Windows-path case (grep for 'C:' / backslash finds none). Images are unaffected because images.ts resolves via URL.

### Suggested direction
Resolve links the same way images are classified (new URL against a file: base) or resolve in Rust; add Windows-path unit tests.
