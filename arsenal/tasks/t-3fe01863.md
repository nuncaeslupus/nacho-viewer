### Cuts and moves
- [ ] **[ci-config] Three release-build jobs run on every PR push** (0 tests) — `package` (deb+AppImage release build, 45 min timeout), `windows` (NSIS installer) and `macos` (universal dmg, two Rust targets) run on every pull_request push. The windows/macos legs exist for 5 export tests each; the installer build after them gates nothing and is uploaded 'to check by hand'. `.github/workflows/ci.yml:39-171`
  - Protection lost: small: a packaging break or .deb >20 MB is found on main (or on PRs touching src-tauri/packaging) instead of on every PR; release.yml rebuilds all three anyway
  - Action: Keep `cargo test export` on windows/macos but gate the `tauri build` + upload steps (and the whole `package` job) with a paths filter (src-tauri/**, packaging/**, package*.json, ci.yml) or `if: github.event_name == 'push'` / a `build-installers` label. Splitting into a separate workflow lets `paths:` do it.
- [ ] **[ci-config] No path filter: docs-only changes run all five jobs** (0 tests) — ci.yml triggers on every pull_request with no `paths`/`paths-ignore`. The repo has docs/, status/, site/, arsenal/, claude-arsenal/, README that cannot affect any job. flatpak.yml and pages.yml already use path filters, ci.yml does not. `.github/workflows/ci.yml:3-6`
  - Protection lost: none - those paths are not inputs to lint, tests or builds (check biome's include list before adding docs/ if it lints markdown/json there)
  - Action: Add `paths-ignore: ['docs/**','status/**','site/**','arsenal/**','claude-arsenal/**','**/*.md']` to both triggers (if `check` is a required status, use a job-level changed-files guard instead so the check still reports).
- [ ] **[ci-config] e2e job builds the frontend twice** (0 tests) — The e2e job runs `npm run build` (tsc + vite build) and then playwright's webServer runs `vite build --mode e2e` again. The first build's output is not what the tests serve, and tsc already runs in `check` via `make lint test` -> `dist`. `.github/workflows/ci.yml:189; playwright.config.ts webServer.command`
  - Protection lost: none - typecheck covered by the `check` job
  - Action: Delete the `- run: npm run build` step from the e2e job.
- [ ] **[slow-tier] Perf budget e2e specs run on every push in two browsers** (5 tests) — e2e/perf.spec.ts (5 tests, 120 s timeout each, 1 MB render / 20 mermaid diagrams / long-task budgets) runs in chromium and webkit on every PR. Timing-budget tests on shared runners are the slowest and flakiest part of an e2e job. `e2e/perf.spec.ts:35,70-240`
  - Protection lost: small: a perf regression is caught on main/nightly rather than in the PR
  - Action: Measure first (`npx playwright test --reporter=list`); only if perf.spec dominates, tag it @perf and run it on push-to-main, keeping the other 33 e2e tests per PR.

### Keep
- src/ui/shell.test.ts (36 tests / 734 lines for a 1600-line shell.ts) - behaviour through a fake backend, not mock-pinning
- src/render/sanitize.test.ts, svg.test.ts, user-css.test.ts - security paths (HTML/SVG/CSS sanitising)
- src/strings.test.ts and src/ui/budget.test.ts - one test each; they look like meta tests but enforce real product invariants (no hardcoded UI text, no dialog capability) cheaply
- Rust tests in scope.rs, config.rs, export.rs, pdf_links.rs - filesystem scope and export paths, 1-6 tests per module
- e2e parity/print/theme/images specs - real-engine rendering that jsdom cannot cover; chromium + webkit is justified because the app ships on WebKit
- scripts/*.test.sh (3 files, 153 lines) - release-asset and apt-repo checks
