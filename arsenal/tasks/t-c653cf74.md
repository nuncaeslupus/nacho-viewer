**Where:** `.github/workflows/release.yml:72-86, .github/workflows/channels.yml:102-105, .github/workflows/ci.yml:29-32`

### Finding
The build job that receives TAURI_SIGNING_PRIVATE_KEY(+PASSWORD) and a contents:write token runs tauri-apps/tauri-action@v0, dtolnay/rust-toolchain@stable and Swatinem/rust-cache@v2 by mutable ref. A moved tag or compromised action can exfiltrate the key that every installed copy trusts for self-update, or tamper with the bundles. channels.yml likewise runs snapcore/action-build@v1 / action-publish@v1 next to store credentials.

### Evidence
Read the workflows: no action is pinned to a commit SHA anywhere; the signing secrets are in the env of the tauri-action step in the same job as the other actions and npm ci.

### Suggested direction
Pin every action to a full commit SHA (Dependabot can bump them), and consider signing in a separate minimal job that only receives built artifacts.
