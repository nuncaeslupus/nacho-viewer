### Finding
The debouncer suppresses an event when the file's mtime (ms) equals the last reported one, to ignore inotify open/read events. On filesystems with coarse mtime (FAT/exFAT 2 s, some SMB/NFS mounts) a second save within the same tick, or a replace that preserves mtime (cp -p, rsync -t), is never reported and the tab shows stale content. The frontend comment claims the opposite ('a coarse or older mtime still reloads').

### Evidence
Traced: reported.insert(path, mtime) != Some(mtime) is the only gate before emit; DocumentChanged::of carries only mtime. Not reproduced on a coarse-mtime filesystem.

### Suggested direction
Include size (or a cheap content hash) in the dedupe key, or filter on the notify event kind (modify/create/rename) instead of mtime.
